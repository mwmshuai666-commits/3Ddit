# 3D 场景数据接入方案（能量管道显隐 / 方向 / 颜色等）

> 目标：让能量管道这类节点的属性可以由外部数据驱动（如 `value < 0` 隐藏管道、`dir` 决定流动方向、阈值决定颜色），
> 且「编辑器里预览的效果」和「导出场景在播放器里跑的效果」一致。

## 一、现状架构（已核对代码，接入点就在这些地方）

| 层 | 文件 | 事实 |
| --- | --- | --- |
| Schema | `src/editor/schema/sceneSchema.js` | 节点参数全在 `catalog.defaultProps` + `catalog.form`；form 字段同时驱动 Inspector 表单，是「字段清单」的唯一声明处 |
| Store | `src/editor/store/editor.js` | `editor.doc` 是纯 JSON 单一事实来源（Dexie 落盘）；`updateNodeProps(id,key,value)` = 改 props + `engine.updateProps(id, props)`；deep watch → 800ms 自动保存 |
| 引擎 | `src/editor/core/EditorEngine.js` | `entries: Map(nodeId → {wrapper, visual, speed...})`；`updateProps` 按 kind 分派；管道 `pipeSignature` 不变 → `updatePipeLook(visual, props)` 热更颜色/浓度/滚动；`entry.speed / entry.particleSpeed` 每帧读来滚 `flowTexture.uOffset` 和推进粒子 |
| 播放器 | `../babylon-scene-player/src/SceneRuntime.js` | **同构**：同样 `entries`、同样 `createPipeVisual`、同样每帧循环；独立仓库，通过 `scripts/sync-player.mjs` 拷 dist 内联进导出 HTML |

关键结论：
- **颜色已经是热更新路径**（`updatePipeLook`，`pipeSignature` 不含 color，不重建几何）→ 数据驱动颜色零成本。
- **方向 = `speed` 的符号**：现在是 `flowOffset -= entry.speed * dt`，负 speed 即反向；只是 form 限死了 `min: 0`。
- **显隐目前不存在**：需要新引擎入口 `setNodeVisible()`。注意粒子系统 emitter 不在 wrapper 下（每帧按 worldMatrix 写坐标），隐藏必须额外 `ps.stop()`，否则光点继续飘。
- 播放器是另一个仓库，「导出后也生效」必须改造 player 或定格快照。

## 二、方案总览：三层 + 两个运行体

```
外部数据                       文档（纯 JSON）                     运行体
┌──────────────┐   sources  ┌───────────────┐   bindings  ┌─────────────────────────┐
│ HTTP 轮询    │◄──────────►│ doc.sources[] │◄──────────►│ 求值器 evaluate(doc,     │
│ WebSocket    │  dataHub   │               │            │   sourceValues)          │
│ 宿主 JS 注入 │            │ node.bindings │            │   → engine.applyRuntime… │
└──────────────┘            └───────────────┘            └─────────────────────────┘
        ▲                                                          ▲
        └──────── 编辑器（编辑期预览）和播放器（export 后）共用同一份 schema 与求值逻辑 ─┘
```

设计红线：
1. **数据永远不写进 `node.props`**。props 是「人工设定的静态基线」，数据干扰它会：每次心跳触发 800ms 自动保存、把设计态冲掉、导出场景带着瞬时值说不清。数据值只走引擎热更通道。
2. **绑定配置和源定义本身进 doc**（可保存、可导出、可复现）。
3. **绝不碰 `pipeSignature` 字段**（points/radius/filletRadius/radialSegments/tubeSegments）——数据一跳就重建管道 = 卡死。数据只允许驱动「look 级」字段：color / casingOpacity / speed 符号 / repeat / particles / visible。

## 三、数据模型（schema 增量，全部可选，老文档零改动）

```js
// sceneSchema.js —— createDefaultDocument() 里加 scene 级默认
doc.sources = [
  {
    id: 'src_temp', type: 'http',        // http | ws | manual
    url: '/api/v1/device/1/realtime',
    intervalMs: 2000,                    // http 轮询间隔（ws 忽略）
    path: 'data.list',                   // 取嵌套字段的 lodash 风格路径
    params: {},                          // http query 附加
  },
]

// 节点级绑定（挂在每个 node 上）
node.bindings = [
  // 显隐：低于 5 就隐藏（输出 0/1）
  { key: 'visible', source: 'src_temp', field: 'value', map: 'threshold',
    stops: [{ at: 5, out: 0 }, { at: 5, out: 1 }] },
  // 方向：负值反向
  { key: 'direction', source: 'src_temp', field: 'dir', map: 'direct' },
  // 颜色：阈值阶梯
  { key: 'color', source: 'src_temp', field: 'value', map: 'threshold',
    stops: [{ at: 0, color: '#00e5ff' }, { at: 60, color: '#ffd166' }, { at: 85, color: '#ff3b30' }] },
]

// 手动/默认可见性也进文档（SceneTree 眼睛图标可改）
node.hidden = false
```

映射器（纯函数，放 `src/editor/core/binding.js`，编辑器/播放器各拷一份——本项目已有 `textures.js/htmlPanel.js` 双拷贝先例）：
- `direct`：值透传（数字先 clamp 到 form 的 min/max）
- `linear`：`in:[a,b] → out:[c,d]` 线性映射（适合进度条类）
- `threshold`：按 `stops` 阶梯查找（颜色、显隐、枚举都归它）

## 四、数据接入的三种方式（"接入的数据怎么接入"）

| 方式 | 适用 | 实现要点 |
| --- | --- | --- |
| ① HTTP 轮询 | 有 REST 实时/准实时接口 | `dataHub` 里按 `intervalMs` fetch，慢/错时指数退避，保留 lastGood 值（避免一次失败整场景闪回默认） |
| ② WebSocket | 真·实时（秒级以下） | 一个 ws 对多 source（source.wsPath 区分）；断线重连 + staleness 超时置灰 |
| ③ 宿主 JS 注入 | 嵌 iframe/大屏项目 | 导出 HTML 里暴露 `window.twinData.push(sourceId, payload)`；由宿主页面自己的数据层推送。播放器默认源，不依赖任何后端 |

三种方式在 `dataHub` 里统一成 `sourceValues = { [sourceId]: lastPayload }`，下游只看这一个结构——**接入形态可后补，绑定不用改**。

## 五、求值与注入管线

1. **`src/editor/core/dataHub.js`（新）**
   - `start(doc)` / `stop()`：按 doc.sources 起 fetcher/ws；100ms tick（或与 render loop 合流）更新缓存
   - 对外 `dataHub.values`（reactive）+ `subscribe(cb)`；附 `stale`/`error` 状态供 UI 显示「在线/离线」

2. **`store/editor.js` 加 `applyBindings()`（新）**
   - tick 里跑：遍历 `doc.nodes` → `node.bindings` → 取源值 → `evaluate()` → 得到 `{key, value}`
   - **不写 props**；调 `getEngine().applyRuntimeValue(node.id, key, value)`
   - 值没变（===）则跳过；一次性给引擎一个 `patch` 对象而不是每字段一次调用

3. **`EditorEngine.applyRuntimeValue(nodeId, key, value)`（新，本次方案核心）**
   - 按 kind 分派到最小代价热更，**禁止触碰 geometry**：
     - `pipe.color / casingOpacity / repeat` → 复用 `updatePipeLook(visual, props)`（现成，签名已确认不含 color）
     - `pipe.direction` → `entry.dir = ±1`，渲染循环里 `flowOffset -= entry.speed * entry.dir * dt`，粒子同步取符号
     - `pipe.particles` → 复用 `setPipeParticles`
     - 任意 kind `visible` → `setNodeVisible(nodeId, !value)`（见下）
   - 引擎内每帧循环已有，dir 只是多乘一个系数，无额外成本

4. **显隐落地细节（`engine.setNodeVisible(nodeId, visible)`，新增）**
   - `primitive / model / html / web / effect`：`wrapper.setEnabled(v)`（test `entry.object.getClassName()` 兜底）
   - `pipe`：`visual.tube.setEnabled + visual.casing.setEnabled` **且** 粒子 `ps.start()/ps.stop()`（emitter 不随 wrapper 禁用，必须单独处理）；同时记录 `entry.visible`，速度推进在隐藏时短路
   - `light`：`object.setEnabled(v)`（Babylon Light 继承 Node，支持）
   - 手动显隐写 `node.hidden`（进 doc 可保存），数据显隐走 runtime 覆盖——同一入口两种来源，`hidden` 是基线、数据态是叠加。

## 六、UI（编辑器侧，简版即可启动）

- **Inspector 表单行**：颜色/开关/下拉行尾加一枚小「⌷」图标 → 打开 BindingDialog：选 source → 选 field → 选映射（direct/linear/threshold）→ 阈值表（值→色值/0/1 编辑）。
- **SceneTree**：节点名称前加数据在线小点（绿=在跑、灰=stale）；眼睛图标切 `node.hidden`。
- 绑定行在表单里回显「← 绑定：temp.value」，点击可解绑。

## 七、导出 / 播放器（协议先行，两端同步）

1. **导出零改动**：`sources` / `bindings` 是 doc 原生字段，`buildExportDoc` 的 `JSON.parse(JSON.stringify(doc))` 自动带走。
2. **播放器升级（外部仓库，二期工程）**：`SceneRuntime.js` 与编辑器同构，改造点一一对应：
   - `loadDocument` 后 `applyBindings` 起一个 `setInterval` tick
   - 加同签名 `applyRuntimeValue`（pipe 分支与编辑器逐行等价）
   - `manual` source 默认开启：宿主通过 `window.twinData.push(id, payload)` 注入
   - 升级后 `npm run sync:player` 重新同步（predev/prebuild 会自动跑）
3. **过渡期兜底**：导出面板加一个「把当前数据态定格为静态值」勾选（写入 props 快照），player 没升级也能看。

| 阶段 | 内容 | 验收 |
| --- | --- | --- |

## 九、风险与坑（提前避开）

- **自动保存噪音**：数据值绝不能写 `editor.doc` 的任何被 deep-watch 到的位置（`markDirty` 会每 800ms 全量存库）。
- **重建风暴**：`pipeSignature` 字段数据不可达；`applyRuntimeValue` 里只走 look 更新。
- **粒子显隐**：不 `stop()` 的话隐藏的管道继续飘光点（emitter 是世界坐标，不吃 wrapper 的 setEnabled）。
- **颜色抖动**：threshold 映射做好滞回（hysteresis）或限频（≥200ms 才响应一次），`Color3.FromHexString` 缓存化。
- **CORS**：编辑器直连后端要 CORS；大屏嵌入场景优先 ws / 宿主注入。
- **播放器不同步**：老 player 遇到 `bindings` 未知字段按静态 props 渲染（不崩但不动）——必须 P3 或走定格导出。
- **两个仓库双拷贝**：`binding.js` 的求值器必须保证编辑器/player 逐行一致，建议加一个单测文件两边共跑（P3 顺手做）。

## 十、需要你确认的三个决策

1. 数据源实际形态：REST 轮询 / WebSocket / 宿主页面 JS 注入？（决定 dataHub 先做哪个）
2. 「方向」语义：反转流动方向（speed 取负）就够，还是要管道整体反向（points 逆序）？
3. 播放器这期是否升级：升级=导出后数据也活；不升级=先做编辑期接入 + 定格导出兜底。

## 附 3：联调排障记录（用户实测反馈的问题与根因）

| 现象 | 根因 | 修复 |
| --- | --- | --- |
| `this._applyHiddenBaseline is not a function` | 往引擎插方法时漏了方法本体（构建查不出的运行时漏网） | 补方法 + 全量「调用 vs 定义」审计流程 |
| 接入后场景没反应 / 正反和颜色都不动 | ①特效节点（柔性管道等）的颜色/流向在引擎侧未实现；②一个坏绑定抛异常会中断整轮 applyBindings | ①DatavEffect.vue 增加「组件 props 覆盖」通道（颜色直通、direction→speed 符号）；②binding.js 色值格式校验 + 注入 try/catch 隔离 |
| 「试一下」点了没反应 | 弹窗草稿用 `watch(() => props.open)` 回填，但弹窗是 v-if 新挂载 + open 常量 true，**watch 永不触发** → sourceId 为空、stops 为空 | `immediate: true` + `:key` 强制新状态 + 保存拒绝无源绑定 + 试一下加兜底值 |
| DOM 报错 `#00e5ff / true cannot be parsed` | stops/below 净化条件写反（非颜色字段的字符串色值被保留，灌进 number 输入框） | 颜色字段收字符串、其余强转数字（init 与 save 双路净化） |
| 用户配了但 snapshot 显示 sources/bindings 全空 | 没先建源就保存被防呆拦截 / 点了遮罩 Esc 取消 | 保存拒绝时 console.warn 明示；操作顺序写进 README |
| 数据全通但颜色不变 | **对颜色字段选了「透传」映射**——原始数字直接当色值必然无效 | 新建绑定时颜色/开关默认「阈值阶梯」；透传+颜色弹窗红字警告；预览显示「原始值 X → 无效，已忽略」 |
| 控制台命令跑不了 | 调试入口挂在 `__editorStore.dataDebug` 下，告诉用户的名字是 `__dataDebug` | 顶层 `window.__dataDebug` 直挂（非 DEV 门控） |
